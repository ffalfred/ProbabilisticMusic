# V2 — Expressive Interpretation Engine

> **Beta.** V2 works, but the defaults in `config.yaml` and `src/transition_table.yaml` are starting estimates — tune them by ear.

---

## What is V2?

In standard mode (V1), the tool renders your score the same way every time (unless you use probabilistic parameters). Every event has the same loudness, timing, and effects each run.

V2 adds a layer of **musical interpretation** on top. It reads the `dynamics:` markings in your score — marks like `p`, `f`, `sfz`, `cresc` — and decides *how to interpret them expressively* before rendering. The result is different every run: different phrasing, slightly different timing, different amounts of reverb, different attack shapes.

The variation is not random noise. It's driven by a model of musical performance: how real performers react to dynamic context, phrase position, and the history of what they just played.

---

## How to turn V2 on

### In the editor

In the **Interpreter** workspace, add one or more Golems and press Play.

### From the terminal

Open `config.yaml` (in the ProbabilisticMusic root folder) in any text editor and change:

```yaml
engine: v2
```

## Adding dynamics to your score

V2 needs a `dynamics:` section in your score. Without it, V2 uses a neutral default for every event.

```yaml
dynamics:
  - t: 0.0
    marking: p

  - t: 10.0
    marking: mp

  - t: 19.0
    marking: f

  - t: 21.0
    marking: sfz

  - t: 24.0
    marking: subito_p

  - t: 30.0
    marking: cresc
    duration: 8.0        # how long the crescendo lasts in seconds

  - t: 38.0
    marking: ff
```

> Note: V2 uses `marking:` (not `mark:` like in V1 dynamics). Both can coexist in the same score.

## Supported dynamic markings

### Volume levels (soft to loud)

| Marking | Meaning |
|---------|---------|
| `ppp` | very very quiet |
| `pp` | very quiet |
| `p` | quiet |
| `mp` | medium quiet |
| `mf` | medium loud |
| `f` | loud |
| `ff` | very loud |
| `fff` | very very loud |

### Expressive markings (instantaneous)

| Marking | What V2 does with it |
|---------|----------------------|
| `sfz` | Sharp accent. Then the next 1–2 events are pulled quieter — as if the performer is withdrawing after the outburst. |
| `fp` | Loud attack that immediately collapses to soft. |
| `subito_p` | Sudden jump to quiet with no transition. |
| `subito_f` | Sudden jump to loud with no transition. |

### Gradual (require `duration:`)

| Marking | What it does |
|---------|-------------|
| `cresc` or `crescendo` | Gradually gets louder over `duration` seconds |
| `decresc`, `decrescendo`, or `diminuendo` | Gradually gets quieter over `duration` seconds |

## What V2 changes

V2 tracks a 12-dimensional "performance state" through the piece and applies it in two places.

**Per event** (always on):

| Parameter | Applied as |
|-----------|-----------|
| `timing_offset_ms` | Slight timing shift earlier or later (±50 ms) |
| `attack_shape` | Longer or shorter fade-in |
| `release_shape` | Longer or shorter fade-out |

**Across the whole mix**, for the dimensions listed in `mix_dims` (Interpreter → mix dims; default: `gain_db` only):

| Dimension | Applied as |
|-----------|-----------|
| `gain_db` | Loudness curve. With golems active this *replaces* the score's dynamics envelope. |
| `brightness` | High-shelf EQ around 4 kHz (0 = −8 dB, 0.5 = flat, 1 = +8 dB) |
| `filter_cutoff` | Low-pass filter, in **Hz** (20–20 000) |
| `filter_resonance` | Resonant peak at the cutoff (used with `filter_cutoff`) |
| `reverb_wet` | Reverb **added on top** of the mix: 0 = none, 1 = as loud as the original. The original stays at full level, and the reverb's tail rings on past the end of the piece. |
| `stereo_width` | Mid/side width: 0 = mono, 0.5 = as recorded, 1 = twice as wide. Stereo pieces only (the checkbox is dimmed when the loaded audio is mono). Each character has its own width (sparse 0.3, lyrical 0.5, dramatic 0.7, turbulent 0.8); it wanders with the character and moves together with the reverb (they are linked in the model); the dynamics markings don't pull it. |

`overdrive_drive`, `pitch_dev_cents` and `dynamic_center` are tracked and shown in the trace, but not applied to the audio yet.

Phrase gain and fades (`phrases:`) apply whether or not golems are active.

## How the engine behaves in practice

The model is described in `theoretical_foundation_v2_update_revised.md`. What the code actually does at each step:

1. **Momentum** — the state continues from its last two values (AR(2), `A1`/`A2`), drifting toward the golem character's resting values.
2. **Target pull** — each dynamic marking defines a target loudness (and brightness, reverb, cutoff). The state is pulled a fixed fraction of the way toward it each step, blending toward the *next* marking shortly before it arrives (`transition_blend`, `transition_shape`). This pull is what makes the performance follow the score.
3. **Kalman update** — the marking window is also used as a Kalman observation. With the current transition table its corrections are small (well under 1 dB), so in practice steps 1, 2 and 4 shape the result.
4. **Sampling** — the value used for the audio is drawn around the current state with the golem's distribution (Gaussian, Laplace, Cauchy, mixture, …).

The engine takes a step at every marking, every event, every start/end of a score element (phrase, FX range, tempo range, articulation, golem), and every `trace_step` seconds (default 0.5). Because each step applies the pull and the momentum once, **adding or removing score elements changes how many steps happen and therefore the shape of the performance**, even where the new element itself is silent.

## Golems

Golems assign an expressive character to a time range — see [interpreter_guide.md](interpreter_guide.md). Built-in Kalman characters: `dramatic`, `lyrical`, `sparse`, `turbulent`. Built-in random-walk characters: `rw_free`, `rw_drift_up`, `rw_reverting`. Overlapping golems are blended by weight, with optional fade-in/out.

## config.yaml reference

```yaml
engine: v2          # v1 = plain rendering, v2 = golem interpretation
seed: null          # integer = reproducible run, null = new run each time

v2:
  A1: 0.7           # momentum: weight of the previous state
  A2: 0.2           # momentum: weight of the state before that (A1 + A2 < 1)
  Q_base: [...]     # how far each of the 12 dimensions may drift per step
  lambda: 0.7       # how far ahead the performer "knows" the score (0.3 = sight-reading)
  eta: 0.3          # how much recent surprises loosen the performance
  xi: 0.05          # strength of the pull toward upcoming markings
  drama_weights:    # what makes a marking significant
    distance: 0.4
    structural: 0.3
    contrast: 0.2
    boundary: 0.1
  window_size: 3    # how many recent markings form one observation
  k_look: 10        # how many markings ahead to look
  vol_window: 10    # how many recent steps feed the "surprise" measure
  cold_start_outputs: {...}   # starting state before the first step
```

Optional `v2:` keys (also set by the Interpreter's Global Settings panel): `trace_step`, `timbral_pull`, `salience_alpha/beta/gamma/delta`, `salience_clamp`, `omega_smooth`, `clip_method`, `physical_limits`.

## Reproducible runs

A run is fully determined by its seed: the random values in the score (ranges and distributions), the golem performance, and the Morphogenics plugins all draw from it.

```yaml
seed: 42     # the same result every time
seed: null   # a different result every time
```

- From the terminal, the seed used is printed at the start of each run.
- In the editor, set the seed in the Interpreter seed box. Every render returns the seed it used.
- Concerto video downloads save the seed next to the output, so an interrupted download resumes with exactly the same audio.

When using V2 from the terminal, each run produces a numbered file:

## Tuning

- **Per-golem character** (Interpreter → golem editor): `Q_scale` (more/less variation), `obs_weight` (how closely it follows the markings), `A1`/`A2` (momentum), the sampling distribution, and `transition_blend` / `transition_shape` (how early and how smoothly it moves toward the next marking).
- **Globally**: `Q_base` in `config.yaml` sets the per-dimension variation; `timbral_pull` sets how strongly brightness, reverb and cutoff follow the dynamics.

Render the same score 5–10 times with `seed: null` and listen. If every run sounds the same, raise `Q_scale`; if it sounds chaotic, lower it or raise `obs_weight`.
