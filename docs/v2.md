# V2: the expressive interpretation engine (golems)

This page covers how golems turn a score into a performance, what they read from the score, what each of the 13 dimensions does to the sound, and the `config.yaml` settings. For using it in the editor, see the [Interpreter guide](interpreter_guide.md).

---

## What V2 adds

The plain renderer (V1) plays the score as written: the same loudness, timing and effects every run, apart from the score's own probabilistic values. V2 adds a **performer**. It reads the score's dynamic markings, hairpins and phrases, keeps a 13-dimensional **performance state** (loudness, brightness, timing, touch, space, filter, width, drive, intonation, compression, tempo), and moves that state through the piece the way a performer's choices move. It anticipates, has momentum, follows the markings and adds its own variation. Each run is a different performance; a seed makes one repeatable.

Golems are the performers. Each covers a time range with a character (a preset or your own settings); overlapping golems blend.

- **Editor:** in the Interpreter, add golems and play in **Interp** mode.
- **Terminal:** set `engine: v2` in `config.yaml`. The golems and mix dims come from the score's own `golems:` and `mix_dims:` lists (as the editor writes them when a score is saved with its golems); `python main.py` doesn't read interpretation files.

## What the engine reads from the score

### Dynamics

Point markings set a level at a moment; hairpins move between levels over a range:

```yaml
dynamics:
  - {t: 0.0,  mark: p}
  - {from: 6.0, to: 12.0, mark: crescendo}   # hairpin: a range
  - {t: 14.0, mark: f}
  - {t: 21.0, mark: subito_p}
  - {t: 28.0, mark: sfz}
```

`mark:` and `marking:` both work.

| Marking | Level / effect |
|---|---|
| `ppp` `pp` `p` `mp` `mf` `f` `ff` `fff` | levels 0.05, 0.10, 0.20, 0.45, 0.65, 0.85, 1.00, 1.20 (as amplitude; `f` ≈ −1.4 dB, `p` ≈ −14 dB) |
| `crescendo`, `cresc`, `cr` / `decrescendo`, `decresc`, `diminuendo`, `dim`, `decr` | a **range** (`from` / `to`): the level ramps to the next point marking, or to ×2.5 / ×0.4 without one, then holds |
| `subito_p` / `subito_f` | `p` / `f` arriving at once, with no approach |
| `fp` | settles at `p`, with no approach |
| `sfz` | an accent: no approach, and the level stays where it was |

The Composer's dynamics envelope and the golems use the same levels and hairpin rule. Before a marking (other than subito, `fp` and `sfz`), a Kalman golem starts moving toward it, as early and along the curve its **transition lead** and **shape** set.

### Phrases and events

- **Phrases** (`phrases:` with `from` / `to`) mark phrase boundaries, which add to a marking's drama. The tempo dimension broadens into each phrase end.
- **Events** carry the per-note dimensions (timing, attack, release, pitch). The engine also takes a step at every event.

## The 13 dimensions

| # | Dimension | Range | Applied as | Heard when |
|---|---|---|---|---|
| 0 | `gain_db` | −40 … +6 dB | Loudness curve on the mix; replaces the score's dynamics envelope while golems are active | `gain_db` in `mix_dims` (default) |
| 1 | `brightness` | 0 … 1 | High shelf at 4 kHz: 0 = −8 dB, 0.5 flat, 1 = +8 dB | `brightness` |
| 2 | `timing_offset_ms` | ±50 ms | Each event placed earlier / later | always (events) |
| 3 | `attack_shape` | 0 … 1 | Fade-in length ×0…×2 and curve (power 4^(2·(a−0.5)): low = fast rise, high = slow swell); 0.5 = as written | always (events) |
| 4 | `release_shape` | 0 … 1 | Fade-out length ×0…×2 and curve (low = held then cut, high = long decaying tail) | always (events) |
| 5 | `reverb_wet` | 0 … 1 | Reverb added on top (0 none, 1 as loud as the original); the tail rings past the end | `reverb_wet` |
| 6 | `filter_cutoff` | 20 … 20 000 Hz | Resonant low-pass, following the trace continuously | `filter_cutoff` |
| 7 | `filter_resonance` | 0 … 1 | That filter's Q: 0 = Butterworth (no peak), 0.5 ≈ +9 dB peak, 1 ≈ +22 dB | with `filter_cutoff` |
| 8 | `stereo_width` | 0 … 1 | Mid/side: 0 mono, 0.5 as recorded, 1 twice as wide | `stereo_width` (stereo only) |
| 9 | `overdrive_drive` | 0 … 1 | tanh saturation at +24·d dB mixed in by d, 2× oversampled; 0 = untouched | `overdrive_drive` |
| 10 | `pitch_dev_cents` | ±50 cents | Each event slightly sharp / flat (a tiny speed change; pitch-locked events re-pitched) | `pitch_dev_cents` (events) |
| 11 | `dynamic_center` | −30 … 0 dBFS | Compressor threshold (2:1, 10 ms / 150 ms, half make-up gain) | `dynamic_center` |
| 12 | `tempo` | ±30 % | Rubato: playback rate 1 + tempo/100, in one time-stretch pass with the score's tempo ranges | `tempo` |

`mix_dims` is the list of dimensions applied (the Interpreter's mix-dim checkboxes, or `mix_dims:` in a score or interpretation). The per-event dimensions 2–4 always apply when there are events. Phrase gain and fades apply with or without golems.

## How a Kalman golem moves

The engine takes a **step** at every marking, every event, every start/end of a score element (phrase, FX range, tempo range, articulation, golem), and every `trace_step` seconds (default 0.5). At each step:

1. **Momentum and home.** The state continues from its last two values (AR(2), `A1`, `A2`) and relaxes toward the character's **home values**: its resting brightness, width, reverb and so on. Gain's home is an offset from the current marking: sparse plays 4 dB under, turbulent 4 dB over.
2. **Pulls toward the score.**
   - **Gain** is pulled toward the marking's level (or the hairpin's curve), blending toward the next marking before it arrives.
   - **Brightness, reverb and cutoff** are pulled toward dynamics-linked targets (louder = brighter, wetter, more open), with strength `timbral_pull` (the editor's **pull**).
   - **Tempo** is pulled toward its rubato target:
     - forward by up to 6 % while the dynamics rise (crescendos, approaching a louder marking);
     - back while they fall;
     - −15 % at the end of each phrase and the last note, broadening over the last 2 s;
     - all scaled by the character's `rubato`.
3. **Anticipation.** The upcoming markings pull ahead, weighted by familiarity `λ` (0.2 sight-reading … 0.95 memorised) and the φ mask / scale.
4. **Kalman update.** The window of recent markings is an observation (the transition table's `H` and `R`), weighted by `obs_weight`.
5. **Noise and sampling.** Noise per dimension is `Q_base`, scaled by:
   - the character's `Q_scale`;
   - its `timing_scale` (timing only);
   - the drama of the marking;
   - recent surprises (`eta`).

   The value used for the sound is drawn around the state with the golem's distribution (Gaussian, Laplace, Student-t, Cauchy, beta, bimodal, mixture…), then clipped to the physical limits.

Because each step applies the pulls and the momentum once, adding or removing score elements changes the number of steps, and so the shape of the performance, even where the new element itself is silent.

### Random-walk and discrete golems

- **Random walk:** each dimension takes a step of `step_size` with optional `drift`, mean reversion toward home (`mr_dims`, `mr_target`), correlation between dimensions, a breathing cycle and a distribution. It ignores the markings.
- **Discrete:** holds the values it is given.
- **Mixed types:** where types overlap, Kalman wins; random walk and discrete apply only where all active golems share that type.

### Blending golems

Overlapping Kalman golems blend their settings by weight × fade (`weight`, `fade_in`, `fade_out`, `fade_curve`). The strongest one at a moment supplies its distribution and transition settings; with `dist_blend: mixture` the others add spikes to it. A golem's own settings (for example `A1`, `lam`, `timing_scale`, `rubato`) override its preset's.

## config.yaml reference

```yaml
engine: v2          # v1 = plain rendering, v2 = golem interpretation
seed: null          # integer = reproducible run, null = new run each time

v2:
  A1: 0.7           # momentum: weight of the previous state
  A2: 0.2           # momentum: weight of the state before (A1 + A2 < 1)
  Q_base: [0.5, 0.04, 250.0, 0.04, 0.04, 0.04, 4000.0, 0.05, 0.04, 0.05, 8.0, 1.0, 0.5]
                    # noise per dimension, in the order of the table above
  lambda: 0.7       # familiarity: how far ahead the performer knows the score
  eta: 0.3          # how much recent surprises loosen the performance
  xi: 0.05          # strength of the pull toward upcoming markings
  drama_weights:    # what makes a marking significant
    distance: 0.4
    structural: 0.3
    contrast: 0.2
    boundary: 0.1
  window_size: 3    # markings per observation
  k_look: 10        # markings to look ahead
  vol_window: 10    # recent steps feeding the "surprise" measure
  cold_start_outputs: {...}   # state before the first step (all 13 dims)
```

Optional `v2:` keys, also set by the Interpreter's Global Settings and top bar:
- `trace_step`: seconds between regular steps; 0 = only at score elements.
- `timbral_pull`: how strongly brightness, reverb and cutoff follow the dynamics.
- `salience_alpha` / `beta` / `gamma` / `delta`, `salience_clamp`, `omega_smooth`: the drama weighting.
- `clip_method`: `hard` or `soft`.
- `physical_limits`: a 13×2 list of `[min, max]`.

**Older files.** Settings written when the state had 12 dimensions still work. A 12-value `Q_base`, or a golem's 12-value per-dimension vectors (A1/A2, Q base, φ mask, inflate, σ caps, random-walk steps, drift, mean reversion, correlation matrices, physical limits), are padded with neutral values for tempo.

## Reproducible runs

A run is fully determined by its seed: the random values in the score, the golem performance, and the Morphogenics plugins all draw from it.

```yaml
seed: 42     # the same result every time
seed: null   # a different result every time
```

- From the terminal, the seed used is printed at the start of each run.
- In the editor, the seed box fills with the seed of the performance you played or traced; the trace always shows the performance that was played.
- Concerto video downloads save the seed next to the output, so an interrupted download resumes with the same audio.

From the terminal, each V2 run writes a numbered file: `output/output_<score>_<audio>_001.wav`, `_002`, …

## Tuning

- **More or less variation:** `Q_scale` per golem, or `Q_base` per dimension globally.
- **Closer to the markings:** raise `obs_weight`; lower it for a freer performer.
- **Smoother or more jittery:** `A1` / `A2` (momentum); the editor's **Smoothness** slider.
- **Earlier preparation:** `transition_blend` (lead) and `transition_shape`; `lam` (familiarity).
- **Timing:** `timing_scale` per golem (1 ≈ 20 ms spread).
- **Rubato:** `rubato` per golem (0 strict … 2 very free), heard with the `tempo` mix dim.
- **Colour following loudness:** `timbral_pull` (0 free … 1 strict).

Render the same score 5–10 times with no seed and listen. If every run sounds the same, raise `Q_scale`. If it sounds chaotic, lower it or raise `obs_weight`.
